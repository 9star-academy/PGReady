# PGReady v0.1 实施计划

**目标** — 在 Ubuntu 24.04 LTS 和 Debian 13 的 APT PostgreSQL 实例上，通过中文数字菜单完成首装、建库建账号、备份与恢复，并能选择实例和进行日常排查。

## 1. 确定接口和验收范围

- [x] 核对现有 README、仓库与本机工具。当前仓库只有文档和 Git 忽略规则，本机为 macOS ARM64。
- [x] 确定依赖方向。Go 标准库实现入口和操作调度。通过参数数组调用 Debian PostgreSQL 工具和官方客户端。命令执行、集群身份与数据库地址由共用代码处理。
- [x] 实现 `go.mod`、`internal/command` 和 `internal/cluster`。验证客户端参数与 PostgreSQL 环境隔离、数据库名转义、进程错误传播。

## 2. 并行实现三个模块

- [x] 主机管理代理负责 `internal/host`（菜单 1、2）。发现并精确启动、停止和重启实例，按系统版本检查 APT 软件包，空机安装后重新发现。验证多个集群、已停止集群、APT 无候选包和安装失败。
- [x] 数据库管理代理负责 `internal/pg`（菜单 3、5、6、7）。完成库和账号操作、配置检查、日志和诊断、扩展查询。验证 SQL 标识符、密码输入、角色权限变更和查询调用。
- [x] 备份代理负责 `internal/archive`（菜单 4）。使用自定义格式生成归档，查看归档并恢复到新库。验证目标文件冲突、备份失败的清理、已有库冲突和还原中断。

## 3. 集成菜单与帮助

- [x] 主代理负责 `cmd/pgready`。接通菜单 1～8、`0`、实例切换、操作确认和 `pgready status`。
- [x] 验证首次进入、取消操作、错误后返回、EOF 退出，以及帮助中的端口跟随当前实例。
- [x] 根据实际实现更新 `README.md`。客户端认证写入、补丁应用、跨主版本迁移、扩展安装安排后续版本。

## 4. 验证首版

- [x] 本地通过 `go test -race -cover ./...` 和 `go vet ./...`，格式检查通过。Linux amd64 和 arm64 均成功交叉构建。
- [x] Ubuntu 24.04.5 LTS arm64 和 Debian 13 arm64 虚拟机均从空机通过 PGReady 安装 PostgreSQL，分别验证 PostgreSQL 16 和 17。
- [x] 两台虚拟机均通过真实 SSH 终端创建应用账号、输入密码和成功登录。单库归档恢复到新库后，查询结果与原库的两条样例数据一致。
- [x] 两台虚拟机均验证配置、诊断和扩展查询。分别停止端口 5433 上的实例，端口 5432 的原库仍可查询，帮助中的连接示例显示当前选中的 5433。
